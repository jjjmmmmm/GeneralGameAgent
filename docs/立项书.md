> 组队：独立完成 | 立项日期：2026-08-19（第 1 天）

## 1. 课题概述

**课题名称**：通用游戏智能体（基于 NitroGen 的离线推理评测与可视化）

**参考项目**：
- NitroGen 官网：<https://nitrogen.minedojo.org/>
- 代码仓库：<https://github.com/MineDojo/NitroGen>（仅作参考，独立仓库自研）

**一句话主路径**：
下载官方预训练权重 `ng.pt` 与单款游戏数据分片 → 启动推理服务 → 对测试帧离线批量推理 → 与人类标注对齐计算指标 → 可视化对比 → 归档代码、指标表与实验报告。

**技术底座**：NitroGen 是 500M 参数 DiT（Diffusion Transformer）基础模型，输入单帧游戏画面，输出 8 步手柄动作块（按键 + 双摇杆），经由互联网游戏视频的行为克隆训练得到。

## 3. 必做（MVP）

依据指导书 4.7 节，MVP 全量保留，另加一条扩展（方向：可视化工具）。

### M1 跑通官方 ng.pt 推理，README 可复现
- **给定**：`ng.pt` 权重已下载，Python 3.12 环境安装完成；
- **当**：按 README 步骤执行 `python scripts/serve.py <ng.pt>` 启动推理服务，并提交 1 帧图像的推理请求；
- **则**：服务正常返回手柄动作（按键与摇杆），全程无报错；他人按 README 从零可复现。

### M2 单游戏数据统计与序列可视化（≥500 帧）
- **给定**：已从 `nvidia/NitroGen` 数据集下载同一款游戏 ≥500 帧标注（Parquet）；
- **当**：运行数据统计脚本；
- **则**：输出该游戏按键频率表与摇杆分布图，并导出 ≥10 条序列的可视化图像（帧画面与对应动作标注对齐）。

### M3 离线评测脚本（测试集 ≥200 帧，与 M2 数据隔离）
- **给定**：测试集 ≥200 帧，取自同款游戏但与 M2 统计所用数据不同分片/不同时段；
- **当**：运行评测脚本，对每帧执行模型推理并与标注对齐；
- **则**：输出指标表，包含按键准确率、摇杆均方误差与相关系数，逐帧明细可查。

### M4 zero-shot 基线达标
- **给定**：`ng.pt` 未做任何微调；
- **当**：在 M3 测试集上运行评测；
- **则**：按键准确率 ≥50%，摇杆相关系数 ≥0.4，结果写入指标表。

### M5 第 5 天演示：模型输出 vs 人类标注对比
- **给定**：选定测试集中一段连续帧序列；
- **当**：运行对比可视化；
- **则**：以表格或录屏呈现"帧画面 + 模型预测动作 + 人类标注动作"三者对照，可逐帧核对差异。

### M6 归档：代码、指标表、实验报告
- **给定**：第 8 天结束；
- **当**：检查仓库交付物；
- **则**：评测代码、指标表（Markdown/CSV）、≥3000 字实验报告齐全；模型权重与数据集不入仓，仓库体积 ≤10MB。

### M7（立项扩展·可视化工具）
- **给定**：选定游戏的数据分片与模型预测结果；
- **当**：运行批量可视化脚本；
- **则**：导出 ≥20 段手柄动作曲线（按键时序 + 双摇杆轨迹，模型预测与人类标注双线叠加），每段自动标出两者差异最大的 5 帧并注明差值。

## 4. 不做（明确排除，附原因）

1. **实机 Windows 游戏接入**（`play.py` 真机演示、窗口捕获、虚拟手柄注入）：
   官方 README 明言该模型为单帧感知的 system-1 模型，不具备端到端玩游戏能力，实机演示效果不可控；实时链路（捕获→推理→注入）环境依赖重、排障成本高；每天 4 小时预算下，优先保证可量化、可核对的离线指标。演示口径由 M5 的离线对比承担。
2. **模型微调 / 后训练**（任何形式的参数更新）：
   RTX 5060 8GB 显存微调 500M DiT 余量不足，且与实验室无独显的现实冲突；扩展方向已按指导书"任选一条"选定可视化工具，不再多线作战。
3. **数据过滤管线**（IDLE/无效帧过滤）：
   属扩展方向之一，未入选。做两条扩展会挤占 MVP 主线时间。
4. **与 Open P2P 的对照实验**：
   属扩展方向之一，未入选；且对照需要额外跑通课题六的模型与数据，工作量等于第二个课题。
5. **下载数据集全库**：
   指导书硬性规定"不得下载数据集全库"；全库体积远超本机磁盘与课程带宽预算。仅下载单款游戏的必要分片。
6. **自采游戏数据**（录屏 + 键鼠/手柄日志）：
   该项为课题六的扩展选项，课题七未作要求；缺少采集设备与时间预算。

## 5. 游戏选择规则（第 2 天执行）

从数据集覆盖的游戏中按以下规则选定 1 款：
1. 该游戏可用帧数 ≥2000（保证 500 帧统计 + 200 帧测试且有隔离余量）；
2. 按键分布非退化（非单一按键占绝对主导）；
3. 游戏 ID 存在于推理服务加载的 game mapping 中。
