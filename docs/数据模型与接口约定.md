# 数据模型与接口约定

> D3（2026-08-21）| 依据：SHARD_0088 / Z1r1S--MJS4（rocket_league）真实 parquet 实测
> 单一事实来源：本文件定义主路径全部数据对象与接口约定，各模块实现时以此为准

## 1. 主路径数据流

```
数据分片(SHARD_0088) → [A data_loader] → ChunkMeta
→ [B frame_fetcher] → FrameRecord（帧图像）
→ [D infer_client] → ActionBlock（预测，8 步块）
→ [E evaluator] → MetricRow / EvalSummary
→ [F viz] → 对比图
   [C stats] → 按键频率表
   [G archive] → 归档
```

## 2. 数据模型（5 个核心实体）

### 2.1 ChunkMeta —— chunk 索引

来源：`<video_id>_chunk_XXXX/metadata.json`（逐字段直接映射，无加工）。

| 字段 | 类型 | 示例值（chunk_0000） | 说明 |
|------|------|----------------------|------|
| uuid | str | `"Z1r1S--MJS4_chunk_0000_actions"` | chunk 唯一标识（metadata.json 原字段） |
| video_id | str | `"Z1r1S--MJS4"` | 视频 ID |
| chunk_id | str | `"0000"` | 0 起编号，4 位 |
| chunk_size | int | `1200` | 帧数（≈20 秒 × 60fps） |
| game | str | `"rocket_league"` | 游戏名（game mapping 的键） |
| controller_type | str | `"ps4"` | 采集手柄类型 |
| url | str | `"https://www.youtube.com/watch?v=Z1r1S--MJS4"` | 原始视频源 |
| start_time / end_time / duration | float | `0 / 20 / 20` | 秒 |
| start_frame / end_frame | int | `0 / 1199` | 帧号闭区间 |
| resolution | [int,int] | `[1080, 1920]` | [高, 宽] |
| source | str | `"youtube"` | 视频平台 |
| bbox_controller_overlay | [int×4] | `[26, 784, 372, 273]` | [x,y,w,h] 手柄覆盖层，推理前遮挡 |
| bbox_game_area | [int×4] \| None | 本视频无 | 可选游戏区域 |

### 2.2 FrameRecord —— 逐帧记录

帧获取的输出、推理与评测的输入。

| 字段 | 类型 | 示例值 | 说明 |
|------|------|--------|------|
| frame_idx | int | `0` | 视频内帧号（对齐 end_frame 计算） |
| chunk_id | str | `"0000"` | 所属 chunk |
| timestamp | float | `0.0` | 秒（frame_idx / fps） |
| image | np.ndarray | `uint8 (1080,1920,3)` | BGR 帧，已应用 bbox_controller_overlay 遮挡；推理前转 RGB |
| source_chunk | ChunkMeta | — | 来源引用 |

### 2.3 ActionBlock —— 动作统一格式（标注与预测共用）

评测对齐的关键实体。**标注**来自 actions_processed.parquet（17 键 + 双摇杆）；**预测**来自模型输出（21 键 + 双摇杆 + 8 步块）。

| 字段 | 类型 | 示例值 | 说明 |
|------|------|--------|------|
| buttons | dict[str, bool] | `{"south": True, "east": False, ...}` | 按下=true（17 键，见 2.4 对照） |
| j_left | (float, float) | `(1.0, 0.436)` | 左摇杆 x,y ∈ [-1,1]，(-1,-1) 为左上 |
| j_right | (float, float) | `(0.0, 0.0)` | 右摇杆，同上 |
| source | str | `"human"` \| `"model"` | 标注/预测来源标记 |
| step | int \| None | `0..7` | 仅预测有：8 步块内步号；标注为 None |

标注实体 = 从 parquet 一行构造：17 键布尔（Int32 1/0 → bool）、j_left（List[Float64]→tuple）、j_right（List[Int64]→tuple）。**采集类型差异**：parquet 中 j_left 为 Float64、j_right 为 Int64（本视频右摇杆几乎不用，非零 0%）；构造 ActionBlock 时统一 `float(j) for j in list` 转成 `(float, float)`，与字段表类型一致。
预测实体 = 模型输出经对齐层映射：21 键 → 17 键（**4 个拨片键丢弃或归并**，见 2.4）。

### 2.4 按键对照表（17 键标注 ↔ 21 键模型）

**标注（actions_processed，17 键）**与**模型输出（BUTTON_ACTION_TOKENS，21 键）**的映射：

| 标注键 | 模型键 | 说明 |
|--------|--------|------|
| back | BACK | 一一对应 |
| dpad_down | DPAD_DOWN | 一一对应 |
| dpad_left | DPAD_LEFT | 一一对应 |
| dpad_right | DPAD_RIGHT | 一一对应 |
| dpad_up | DPAD_UP | 一一对应 |
| east | EAST | 一一对应 |
| guide | GUIDE | 一一对应 |
| left_shoulder | LEFT_SHOULDER | 一一对应 |
| left_thumb | LEFT_THUMB | 一一对应 |
| left_trigger | LEFT_TRIGGER | 一一对应 |
| north | NORTH | 一一对应 |
| right_shoulder | RIGHT_SHOULDER | 一一对应 |
| right_thumb | RIGHT_THUMB | 一一对应 |
| right_trigger | RIGHT_TRIGGER | 一一对应 |
| south | SOUTH | 一一对应 |
| start | START | 一一对应 |
| west | WEST | 一一对应 |
| — | RIGHT_BOTTOM | 模型独有（右摇杆拨片），标注无 |
| — | RIGHT_LEFT | 模型独有 |
| — | RIGHT_RIGHT | 模型独有 |
| — | RIGHT_UP | 模型独有 |

**对齐策略**：评测按钮准确率时，模型 21 键 → 丢弃 4 个拨片键（本项目所选游戏右摇杆拨片极少使用，实测 j_right 非零 0%），得到 17 键子集与标注逐键比较。用官方 `actions_processed.parquet` 天然规避自写重映射层。

### 2.5 MetricRow —— 逐帧评测明细

E 模块输出，每测试帧一条。

| 字段 | 类型 | 说明 |
|------|------|------|
| frame_idx | int | 帧号 |
| buttons_hit / buttons_total | int | 17 键逐键比较命中数 / 总数 |
| j_left_mse / j_right_mse | float | 摇杆欧氏距离平方（对照帧） |
| j_left_corr / j_right_corr | float | 摇杆相关系数贡献（对照帧，用协方差累加） |
| source_chunk | str | chunk_id |

### 2.6 EvalSummary —— 评测汇总（M4 指标表）

| 字段 | 类型 | 说明 |
|------|------|------|
| test_frames | int | 测试集帧数（≥200） |
| test_chunks | list[str] | 测试集 chunk 列表 |
| buttons_accuracy | float | 按键准确率（zero-shot ≥50%） |
| j_left_mse / j_right_mse | float | 摇杆均方误差 |
| j_left_corr / j_right_corr | float | 摇杆相关系数（≥0.4） |

## 3. 接口约定（A~F 六模块）

约定形式：函数签名 + 入参 + 成功返回（真实示例）+ 一类常见失败。**每个接口必须有失败例**。

### A. data_loader —— 数据获取

```python
def list_chunks(shard_path: Path, game: str) -> list[ChunkMeta]
```
- 入参：分片根路径（如 `_data/SHARD_0088`）、游戏名（如 `rocket_league`）
- 成功：35 个 ChunkMeta（Z1r1S--MJS4 全部 chunk），首项 video_id=`Z1r1S--MJS4`、game=`rocket_league`
- 失败例：分片路径不存在 → `FileNotFoundError("shard path not found: ...")`；无该游戏数据 → 返回空列表 `[]`（不抛异常，调用方自行判断）

### B. frame_fetcher —— 帧获取

```python
def fetch_frames(chunk: ChunkMeta, out_dir: Path) -> list[FrameRecord]
```
- 入参：单 chunk 元数据、输出目录
- 成功：1200 个 FrameRecord（每帧图像已按 `bbox_controller_overlay=[26,784,372,273]` 遮挡）
- 失败例：视频源不可用（yt-dlp 404 / 地区受限）→ `yt_dlp.utils.DownloadError("Unable to download video ...")`，调用方捕获后可改用相邻 chunk 或记录差距清单

### C. stats —— 数据统计

```python
def button_frequency(actions_parquet: Path) -> dict[str, float]
```
- 入参：parquet 路径
- 成功：`{"right_trigger": 0.321, "east": 0.150, "left_shoulder": 0.127, ...}`（17 键占比）
- 失败例：parquet 缺按键列 → `KeyError("missing column: west")`（若该键从未按下则列仍存在，值为 0；缺列是文件损坏信号）

### D. infer_client —— 推理客户端

```python
class InferClient:
    def predict(self, frame: np.ndarray) -> ActionBlock
```
- 入参：单帧 **RGB** `np.ndarray (H,W,3) uint8`（官方 ModelClient 要求 RGB；FrameRecord 存 BGR，调用前需 `cv2.cvtColor(image, cv2.COLOR_BGR2RGB)`）
- 内部实现：封装官方 `ModelClient.predict`（ZeroMQ REQ，`timeout_ms=30000`）
- 成功：官方返回 `{"pred": {"j_left": [x,y], "j_right": [x,y], "buttons": [...]}}`，经对齐层转 `ActionBlock(buttons={"south": True, ...}, j_left=(1.0, 0.436), j_right=(0.0, 0.0), source="model", step=0)`（8 步块由内部循环 8 次或服务返回）
- 失败例（两类）：
  1. serve.py 未启动 / 无响应超时 → `zmq.Again`（官方 ModelClient 设置 RCVTIMEO=30000ms）；调用方捕获重试或退出
  2. 服务返回异常 → `RuntimeError("Server error: <message>")`（官方 status!="ok" 时抛出）
- **game mapping 依赖（D3 已验证，见 3.1）**：ng.pt 的 `game_mapping_cfg=None`，serve.py 走无条件分支直接可启动，无需适配层

### E. evaluator —— 评测器

```python
def run(test_frames: list[FrameRecord],
        predictions: list[ActionBlock]) -> tuple[EvalSummary, list[MetricRow]]
```
- 入参：测试帧（≥200）与逐帧预测（长度一致）
- 成功：`(EvalSummary(test_frames=200, buttons_accuracy=0.55, j_left_corr=0.42, ...), [MetricRow×200])`
- 失败例：`test_frames` < 200 → `ValueError("test set must have >=200 frames, got 123")`；两列表长度不一致 → `ValueError("frames/predictions length mismatch: 200 vs 199")`

### F. viz —— 可视化

```python
def render_curve(action_pairs: list[tuple[ActionBlock, ActionBlock]], out_png: Path) -> None
```
- 入参：标注-预测逐帧对、输出路径
- 成功：写出 PNG 对比图（双线叠加，≥20 段曲线时逐段标注差异最大 5 帧）
- 失败例：输出目录不存在 → `FileNotFoundError("output dir not found: ...")`（函数不自动建目录，调用方负责）

## 3.1 game mapping 验证结论（D3）

实测 `ng.pt`（1,974,723,762 字节）的 `ckpt_config`：

- `tokenizer_cfg.game_mapping_cfg = None`（非 dict，无 `src_files`）
- 代码路径（`nitrogen/mm_tokenizers.py`、`inference_session.py`）：
  - `from_ckpt` 第 59 行 `if game_mapping_cfg is not None:` 不执行（无路径替换）
  - `NitrogenTokenizer.__init__` 第 111 行 `if config.game_mapping_cfg:` 为 False → `self.game_mapping = None`
  - `from_ckpt` 第 143-145 行 → 打印 `No game mapping available, proceeding without game conditioning`，`selected_game=None`
  - `NitroGen.__init__` `game_mapping=None` → 不建 `game_embedding`，权重无对应参数，`load_state_dict` 不受影响
- **结论：serve.py 可直接启动（无条件分支），无需适配层；M1"按 README 跑 serve.py"可行**
- 附带事实：`model_cfg.vision_encoder_name = "google/siglip2-large-patch16-256"`，首次加载需从 HF 下载（D4 首跑前确保 hf-mirror 可达）

## 4. 用户故事走查（防断链）

沿主路径逐个接口对接，确认输入输出类型链：

1. **取数据**：`list_chunks(_data/SHARD_0088, "rocket_league")` → `[ChunkMeta×35]`
2. **取帧**：`fetch_frames(chunk_0000, frames/)` → `[FrameRecord×1200]`（含 image）
3. **推理**：`InferClient.predict(frame_record.image)` → `ActionBlock(source="model", step=0..7)`
4. **评测**：`run(test_frames[0:200], preds[0:200])` → `(EvalSummary, [MetricRow×200])`
5. **可视化**：`render_curve(zip(labeled, predicted), viz/out.png)` → PNG

**断链检查**：
- B 输出 FrameRecord.image（BGR ndarray）→ D 输入 np.ndarray：✅ 类型一致
- D 输出 ActionBlock(source="model") 与标注 ActionBlock(source="human") 同构：✅ 可成对
- E 输入 frames/predictions 两列表 → F 输入 action_pairs：✅ 长度一致（均由 200 测试帧派生）
- 全部 6 接口均有失败例：✅
- 唯一外部依赖 serve.py：✅ 已验证可直接启动（game_mapping_cfg=None 走无条件分支，见 3.1）
