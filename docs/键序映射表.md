| 方法 | 结论 | 说明 |

## 3. 重要推论（D5→D6 关键转折）

1. **D5 的"前 17 列"假设是错误的**：`south/start/west` 实际在第 18/19/20 列。D5 报告的数字（准确率 85.9%）基于错误对齐，**以本次重算为准（88.2%）**；
2. **zero-shot 模型按键预测极度稀疏**：30 帧测试集只有 8 个按键事件，而标注 right_trigger 按下率 93%。模型没有学会持续按键行为（RL 里油门是常按键）；
3. **PRED_ROW=0 确认（D7）**：相关系数矩阵法排除时序偏移（18 步全测无显著相关），维持官方 cfg 默认，不再是不确定项。

## 4. 对 M4 验收的影响

- 按键准确率（17 键全对比例）会因模型稀疏而虚高（大量 0==0 正确）；
- **M4 必须同时报告触发精确率/召回率/F1**（G3），以"按下事件"为统计口径；
- **D7 归因收口**：摇杆不达标根因 = 无条件 zero-shot 模型能力上限（三假设验证：game conditioning 无接口/PRED_ROW 18 步全测无信号/能力上限）。M4 验收以"能力上限"如实呈现，答辩用三假设验证证据支撑。

## 5. 附加发现（D7）：模型实际输出 18 步动作，非 8 步

- 实测 `pred['j_left']`/`pred['buttons']` shape 为 **(18, N)**（D4 记录过 shape 但未辨析步数）；
- 与 cfg 中 `action_per_chunk=8` 的关系待查（可能 18 = 模型内部步数）；**不影响评测**（PRED_ROW=0 取第 0 步，18 步全测无显著差异已证明）；README 中"8 步动作块"说法已修正为"18 步（实测）"。
