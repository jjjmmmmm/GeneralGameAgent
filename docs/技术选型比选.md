# 技术选型比选

> 第 2 天（2026-08-20）| 选型原则：本人熟悉度 + 9 天内可调试可演示 + 与官方依赖兼容；不追新
> 每个决策至少两个候选，同一组维度比较，写清放弃理由

## 决策 1：推理接入方式

| 维度 | A. 官方 serve.py（ZeroMQ 服务）+ ModelClient | B. 进程内直接调用 InferenceSession |
|------|---------------------------------------------|-----------------------------------|
| 与 M1 验收句吻合度 | 高：验收句即"按 README 执行 serve.py 提交 1 帧推理请求" | 低：偏离官方路径，需自证等效 |
| 改动量 | 零（原样运行官方脚本） | 高：`from_ckpt` 含 `input()` 交互，自动化需复刻构造流程（load_model + 手动传参） |
| 崩溃隔离 | 好：服务进程独立，评测脚本崩溃不卸权重 | 差：每次重跑脚本需重新加载权重（1.97GB，分钟级） |
| 接口开销 | 每帧一次 IPC 往返（本机，毫秒级，非瓶颈） | 无 |
| 依赖 | pyzmq（官方 serve 依赖已含） | 同样需要 nitrogen 包 |
| 风险 | 游戏选择在服务启动时交互一次（人工步骤，可接受） | 代码路径无官方验证 |

**结论：选 A。放弃 B 的理由**：B 为满足自动化必须绕开 `from_ckpt` 自行拼装会话，等于维护一条无官方背书的加载路径，与 M1"README 可复现"的验收口径冲突；且权重常驻评测进程导致每次迭代都要付加载成本。A 的唯一代价是启动服务时手动输一次游戏 ID，可接受。

## 决策 2：可视化库

| 维度 | A. matplotlib（静态 PNG） | B. plotly（交互 HTML） |
|------|--------------------------|------------------------|
| 报告嵌入 | PNG 直接嵌入 Markdown 报告，作业系统与 GitHub 均稳 | HTML 需外部查看器，作业系统正文不友好 |
| 仓库体积 | 单图数十 KB，可控 | 单文件数百 KB 起，挤压 10MB 限额 |
| 交互需求 | 逐帧核对由"表格+静态图"承担（M5 验收口径即表格或录屏） | 交互拖拽属加分非刚需 |
| 本人熟悉度 | 课程常用，基础扎实 | 未系统用过 |
| 依赖体积 | 小 | 大 |

**结论：选 A。放弃 B 的理由**：M5/M7 的验收口径是"表格或录屏可逐帧核对"与"导出 ≥20 段曲线图"，静态 PNG 完全覆盖；plotly 的交互优势无处变现，却带来仓库体积与报告嵌入两个实打实的成本。

## 决策 3：数据处理库

| 维度 | A. polars | B. pandas |
|------|-----------|-----------|
| 与官方一致性 | 官方 mm_tokenizers.py 即用 `pl.read_parquet` | 无官方使用 |
| 读取 Parquet 性能 | 快（多线程） | 慢于 polars |
| API 风格 | 类 pandas，迁移成本低 | 本人更熟悉 |
| 生态 | 足够（本课题只需读表、过滤、聚合） | 最全 |

**结论：选 A。放弃 B 的理由**：官方代码用 polars 读同一批文件，跟随官方可规避 schema 处理差异（R5 风险直接相关）；本课题的数据操作仅读/过滤/聚合，pandas 的生态优势用不上，而 polars 的 API 与 pandas 高度相似，熟悉度差距可在半天内抹平。

## 决策 4（新增）：视频帧获取方式

| 维度 | A. yt-dlp 命令行（脚本化下载片段） | B. 浏览器手动下载 |
|------|-----------------------------------|------------------|
| 可复现性 | 命令可写入 README 与脚本 | 不可复现，依赖人工操作 |
| 时间戳裁剪 | `--download-sections` 按起止时间精确截段 | 需手动剪辑 |
| 批量化 | 可批量处理多个 chunk | 逐个手动 |
| 依赖 | yt-dlp 单命令安装 | 无 |

**结论：选 A。放弃 B 的理由**：M3 测试集 ≥200 帧与 M7 ≥20 段曲线均需批量取帧，手动路径在量与可复现性上都不成立；yt-dlp 是唯一能写进"他人可复现"口径的方案。

## 入选方案风险与对策

| 方案 | 风险 | 对策 |
|------|------|------|
| serve.py | game mapping 的 src_files 指向本地不存在的 parquet，启动即崩 | D2 拿到 ng.pt 后读 ckpt_config 验证；若缺失，D3 写适配层（自研仓库内构造会话，patch 路径）并记入差距清单 |
| matplotlib | 无 | — |
| polars | 不熟悉个别 API | 官方代码可参照；遇阻退 pandas 读、polars 仅对齐官方路径 |
| yt-dlp | 视频源可能失效或地区受限 | 换同游戏其他 chunk；下载失败记差距清单 |
